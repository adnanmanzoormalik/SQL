Logical SQL query execution order
When you write a SQL query, you usually start with SELECT. But SQL does not logically process the query in the order you write its clauses.

SELECT department, AVG(salary) AS avg_salary
FROM employees
WHERE salary > 30000
GROUP BY department
HAVING AVG(salary) > 40000
ORDER BY avg_salary DESC
LIMIT 3;

The logical processing order is:
1. FROM: Identify the source table.
2. WHERE: Filter individual rows.
3. GROUP BY: Group the remaining rows.
4. HAVING: Filter the groups.
5. SELECT: Calculate and choose output columns.
6. ORDER BY: Sort the resulting rows.
7. LIMIT: Restrict the number of rows returned.





SELECT salary * 12 AS annual_salary
FROM employees
WHERE annual_salary > 500000;

In MySQL, this fails because the WHERE clause is logically processed before the SELECT clause defines the annual_salary alias.
You can fix it by repeating the expression:

SELECT salary * 12 AS annual_salary
FROM employees
WHERE salary * 12 > 500000;
Or you can use a subquery or CTE to calculate annual_salary first and filter it in an outer query.
